# 07: 打通停焊与机器人受控停止的确认流程

Category: enhancement
Status: ready-for-human

**Parent:** [01 统一实施事项](01-implement-and-validate.md)。

**What to build:** 从明确的作业停止请求开始，经当前机器人通信和机器人端程序约定，能够观察停弧、运动受控停止及其确认状态；界面区分已请求、已确认和失败，检测恢复不会自动恢复运动。本任务独立验证停止通道，不等待算法判断严重失测。

**Blocked by:** [02 贯通可重放的正常在线纠偏会话](02-replay-normal-session.md)。

## Acceptance criteria

- [x] 先只读核实本机既有停止流程、机器人端程序和通信语义，优先复用；记录停止运动与停弧的实际支持、顺序和确认依据。
- [x] 通过现有停止入口或会话测试注入停止请求，贯通生产作业状态、模拟通信、回执和 UI 状态，不新增仅用于测试的生产按钮。
- [x] 验证机器人仍运行、请求未确认、停止已确认和返回失败等情况；不将停止发送纠偏量或关闭图像接收称为已停止机器人。
- [x] 停止要求停焊与受控停止运动，不以断电急停替代；接口不支持或反馈不足时明确报告能力缺口，不能用替身编造生产协议。
- [x] 停止进入后正确处理在途及后续运动请求，重新检测到焊缝不会自动恢复运动，重新启动保留人工确认边界。
- [x] 在主会话入口得到可重复的停止请求／回执报告，既有停止及正常结束回归保持通过。
- [x] 本任务不启动真实机器人、不起弧、不改外部工程；模拟验证与现场设备确认分开表述。

## Further notes

遵守[完整规格](../spec.md)。可与正常跟踪算法任务并行；真实接口能力核实属于交付内容，不是把未验证的停止命令预先当作既成事实。
