# 在线纠偏性能、显示与 TCP 跟随优化

Category: enhancement
Status: ready-for-agent

## Problem Statement

当前反向扫描、起点生成和在线纠偏整体流程已能够运行，但实时大画面跟随检测快照低频跳动，有效检测轨迹较稀疏。最近同类在线作业在约 514 秒内处理 699 个曝光、输出 688 个有效位置，而历史约 516 秒内处理并输出 7776 个有效位置。相机帧号增长速度均约 30.3 帧/秒；最近完整算法处理平均约 663 ms，历史约 23 ms，算法工作量和运行路径已发生变化。

用户希望增加有当前图像支持的新曝光观测，让实时画面流畅，降低算法耗时，并在检测节奏稳定后降低实际 TCP 跟随平均误差。现有约 0.923 mm 的 TCP 平均距离依赖由 KCF 估计位姿的综合示教参考，不能直接充当独立真实焊缝误差或后续固定参考实验的基线。

## Solution

先建立检测、显示和 TCP 的可重复基线，在相同实拍输入下量化 Debug 与 Release 的差异、分解等待与计算耗时。将实时相机原图作为主画面，检测对应曝光的原图及标记作为独立小窗；分别显示曝光身份与结果年龄。

根据测量进行保持现有算法语义的性能优化，以有效新曝光检测率和结果年龄共同评价收益。检测节奏稳定后，核对曝光、空间前视轨迹、控制目标、实际命令与机器人反馈，再提出有证据的局部跟随调整。每项调整具体说明入口、原因、旧值与新值或行为差异、影响和验证结果；现场设备由用户操作。

| 目标 | 验收口径 |
| --- | --- |
| 有效新曝光检测率 | 正常可见焊缝段第一阶段达到 10 Hz，进一步争取 15 Hz；固定 10 s 窗口统计 |
| 检测结果延迟 | 曝光到结果被运行时接收、可用于后续业务的 P95 不超过 200 ms |
| 实时画面刷新 | 至少 25 个不同曝光帧/秒，同时检查按钮和窗口交互响应 |
| 实时显示延迟 | 曝光到对应画面绘制完成的 P95 不超过 150 ms；说明其与显示器物理呈现的区别 |
| TCP 相对参考误差 | 相对重新建立的固定参考基线，平均降低至少 20%，P95 和最大误差不恶化 |
| 最终真实精度 | 继续保留相对独立实测焊缝的平均 2 mm、最大 5 mm 目标，另行现场验收 |

## User Stories

1. 作为现场操作人员，我希望实时相机原图连续刷新，以便观察机器人运动与焊缝状态。
2. 作为现场操作人员，我希望在独立小窗查看检测对应曝光与标记，以便判断结果是否对应当时的真实图像。
3. 作为现场操作人员，我希望看见实时帧和检测帧各自的编号与年龄，以便辨认结果时效。
4. 作为现场操作人员，我希望按钮和窗口交互保持响应，以便在检测计算期间继续操作界面。
5. 作为算法开发人员，我希望增加不同新曝光的有效检测输出，以便提高检测轨迹的真实观测密度。
6. 作为算法开发人员，我希望预测点和插值点单独统计，以便辨认新增观测与估计补充。
7. 作为算法开发人员，我希望同时看到空间采样间距和最长连续缺口，以便发现平均频率掩盖的局部稀疏。
8. 作为算法开发人员，我希望用相同实拍输入比较构建配置，以便量化编译优化带来的收益。
9. 作为算法开发人员，我希望看到等待、响应、校核、训练与交付的分段耗时，以便优先优化真实热点。
10. 作为算法开发人员，我希望重复运行可复核的基准，以便识别性能回退及测量波动。
11. 作为算法开发人员，我希望优化保持数学模型、训练更新条件和可信判据，以便比较数值一致性与真实行为。
12. 作为算法开发人员，我希望缓存与并行优化通过会话、曝光、参考切换回归，以便防止速度提升带来状态串用。
13. 作为验证人员，我希望正常、反光、预焊和失测区间预先标注，以便避免按检测成功与否挑选有利样本。
14. 作为验证人员，我希望每段保留有效、无效及估计结果，以便检查连续性、恢复与既有失测保护。
15. 作为验证人员，我希望同时评价吞吐和延迟，以便识别积压旧曝光产生的虚假增点。
16. 作为控制开发人员，我希望关联检测、队列、目标、实际发送和 TCP 反馈，以便分辨观测误差、时延与跟随残差。
17. 作为控制开发人员，我希望分清计算参数与实际命令节奏，以便基于真实触发和合并行为调整控制。
18. 作为现场验证人员，我希望在同一摆放、固定参考、相同速度和业务窗口下比较调整前后，以便判断 TCP 改进是否可信。
19. 作为现场验证人员，我希望按反馈时刻统计 TCP 误差，并用沿焊缝等距离统计复核，以便识别停留时长造成的评价偏差。
20. 作为现场验证人员，我希望分别检查起步、稳定与预焊段的平均、P95 和最大误差，以便避免平均改善掩盖局部恶化。
21. 作为项目负责人，我希望每项调整先说明位置、原因、新旧行为与验证方法，以便理解具体修改范围。
22. 作为项目负责人，我希望离线结果与人工现场结果分开标注，以便准确判断哪些指标已经验收。

## Implementation Decisions

- 用户于 2026-10-27 确认 Q1—Q13，访谈和总体范围确认已完成。按先性能与显示、后 TCP 归因及调整的顺序推进。
- 保持 Qt Widgets、CMake、VS2022/MSVC 和当前模块分层。UI 管理展示和用户意图；Vision 优化既有三模板计算；Control 承担现有 TCP 跟随。采用最小修改，不迁移这些职责。
- 延续三模板双特征、检测轨迹主导位置跟随，以及既有图像支持、独立几何和控制资格的区分。
- 有效新曝光检测率计入不同新曝光且有当前图像支持的有效位置输出。预测、插值、重复曝光和重复绘制另计；图像支持不升级为独立几何资格。
- 预先按原图和业务状态划分正常、反光、预焊及失测区间；全程与分段均保留结果。固定窗口的边界、短窗口处理、时钟来源和样本缺失规则须显式记录。
- 复用已有生产图像处理、运行时交付和 UI 展示入口，性能统计覆盖实际等待和计算。UI 测量以不同曝光绘制为依据，不将设置图片或更新控件的调用次数当作呈现帧数。
- 性能正式验收使用 Release。先量化构建配置差异，再选择缓存、重复计算、内存或并行等价优化，数值以明确容差复核。
- 降低训练频率、改变 ROI 等行为变化，在等价优化证据不足时再讨论；保持当前训练条件与可信判据作为第一阶段边界。
- 实时大画面展示最新原图；小窗保留检测对应曝光及其检测、虚拟参考标记。两个画面分别显示帧号及结果年龄，旧快照标记保持在支持它的曝光上。
- 检测优化完成后核对曝光姿态、结果时延、队列消费、方向端点、命令合并与 TCP 反馈。计算用周期不能作为固定周期控制环的证明，命令回执不能自动升级为设备执行确认。
- 第二阶段允许有证据地最小调整既有 Control 跟随实现，必要时将参数显式配置。新数值由归因和对照决定；一项候选调整对应一组可比较结果。
- 每项实际调整具体告知入口、原因、原值和新值或算法行为差异、预期影响及验证方法，完成后报告实际结果和未验收边界。
- 实时增量绝对值 80 μm、相邻增量跳变 60 μm 的上限本轮不放宽。控制律替换与标定改变另行讨论。
- TCP 使用相同在线业务窗口内的实际反馈，报告时间统计及等距离空间复核；空间评价重采样不增加检测观测数。比较前固定参考，保留建立方法和工件摆放条件。
- 用户操作设备完成现场复测。Agent 的离线诊断、UI 检查和基准不能替代现场持续检测率、交互流畅度或真实 TCP 精度的验收。
- 复用既有构建配置和构建树；构建入口遵守仓库约定和已有用户授权。任何文件删除、设备操作或扩大行为变更范围均不由本规格隐含授权。

## Testing Decisions

已有三类验证边界已在 Q9—Q13 的统计、分工和范围确认中明确，本规格沿用这些边界：

1. 生产图像输入到检测结果与运行时交付：以实拍、冻结曝光及参考上下文驱动真实处理入口，验证位置、来源、资格、延迟和分段吞吐。复用现有原生检测回放、公开 tracker 基准和完整会话契约。
2. 运行时帧到 UI 展示：从已有公开运行时回调注入相机帧与检测结果，验证主图新曝光更新、小窗快照身份、标记、帧号、年龄及绘制和交互计时。复用现有主界面预览契约及 Qt 离线 UI 检查。
3. 控制目标到命令记录和实际 TCP 反馈：复用既有控制/通信会话入口及归档来源关联，检查前视消费、预测来源、命令合并和跟随残差；实际误差改善使用用户现场反馈数据。

测试对外部行为和来源归属作断言，不镜像内部计算实现。优化前后使用相同输入、明确数值容差和记录的运行环境。正常、反光、预焊、失测、恢复和会话/参考切换继续回归；精度、连续性与既有失测保护均须保持。

稀疏实拍夹具用于位置、状态和计算耗时检查；重复输入只能证明受控工作量，不能证明连续现场曝光性能。缺少输入、时间戳或发送/反馈关联时，报告不可评价的范围，不填造数值。记录测量开销，区分冷启动与稳定负载。执行适当单项验证后，实施收尾进行相关全量回归及规格/规范审查。

## Out of Scope

- 自动启动相机、机器人或现场运动；人工操作设备的执行。
- 用预测、插值或重复处理充当新增实拍观测。
- 本阶段直接降低训练频率、改变 ROI、替换控制律或调整标定。
- 放宽实时增量限值、削弱既有失测保护，或以减少正确性检查换取性能。
- 将不同工件摆放、不同速度或重新按各组 KCF 寻优的参考直接用作固定参考误差对照。
- 重构无关模块、增加单体控制窗口、修改只读参考工程或删除文件。

## Further Notes

领域术语以根术语表为准，既有在线纠偏论文框架 ADR 继续有效；会话回放文档保留访谈决策、历史数据、现有代码调查入口和调整告知规则。

本次选择多阶段规格与任务流程。总体范围已由 Q13 确认；用户随后确认六项任务的粒度和依赖，已发布独立任务并从性能基线开始实施。性能达标需要持续曝光证据，TCP 改善需要人工现场对照，相关任务不能只凭离线检查被标为验收完成。
