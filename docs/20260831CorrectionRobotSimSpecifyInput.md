# Spec Kit `/speckit.specify` 输入稿：在线/离线纠偏逐帧接入 RobotSim

## 使用方式

将下方“功能描述”整体复制到 `/speckit.specify` 命令之后。该描述已经完成需求访谈，
不应再把全局定位、视觉伺服或完整无设备仿真扩入本特性。

## 功能描述

为现有机器人定位与纠偏应用增加在线纠偏和离线纠偏的逐帧 RobotSim 虚拟参考接入。
系统已经能够连接 RobotSim、获取二维虚拟激光线、三维虚拟激光线和虚拟焊缝点，
Vision 也已经具备消费相机帧、机器人状态和 RobotSim observation 的能力。本特性只补齐
在线/离线纠偏的数据绑定、运行控制、错误处理和可验证的 UI 状态，不重做已有算法。

### 用户价值

操作人员启动离线或在线纠偏后，每个被处理的相机帧都使用该帧到达运行时边界时冻结的
最新机器人状态查询 RobotSim，并将返回的虚拟参考与同一相机帧一起交给 Vision。操作人员
能够确认 UI 展示的 RobotSim observation 就是 Vision 实际消费的那一帧数据，而不是缓存中
来自其他机器人姿态的旧数据。

### 范围和交付顺序

1. 先完成并验证离线纠偏逐帧接入，再直接完成在线纠偏逐帧接入。
2. 离线和在线均满足全部验收条件后，本阶段才算完成。
3. 全局定位只可作为现有公共能力和行为范例使用，不得修改其专属实现逻辑、接口语义、
   信号、数据流或运行行为。
4. 不得修改视觉伺服/IBVS 的现有内容。
5. 不修改 Vision、Localization 或 IBVS 的算法实现；如确有无法绕开的接口缺陷，必须另行
   提出并评估，不能隐式扩大本特性范围。
6. 现有公共能力可以继续复用，但其他工作流已经依赖的行为和契约必须保持兼容。

### 用户场景一：离线纠偏逐帧处理（优先级 P1）

操作人员在真实状态同步模式下启动离线纠偏。每个待处理相机帧到达运行时边界时，系统冻结
当时最新的机器人状态和离线流程上下文，以这份状态查询 RobotSim。查询返回后，相机帧、
机器人状态和 observation 作为不可拆分的一组数据交给 Vision。离线检测继续遵守既有流程，
不改变离线算法和命令生成规则。

验收场景：

- 假设 RobotSim 已连接且存在有效机器人状态，当离线纠偏收到相机帧时，Vision 收到的
  observation frameId 必须与相机帧 frameId 相同。
- 假设连续相机帧到达速度高于 RobotSim 和 Vision 的处理速度，系统最多保留一个在途帧和
  一个可被覆盖的最新待处理帧，不产生持续增长的请求或图像队列。
- 假设帧 100 正在处理且随后到达帧 101 至 105，当帧 100 仍属于当前运行会话时，系统完成
  帧 100，然后只处理最新待处理帧 105。
- 假设离线流程停止，停止后不得再发起新的逐帧 RobotSim 查询，已排队但尚未发起的帧必须
  被清除，迟到结果不得进入新的运行会话。

### 用户场景二：在线纠偏逐帧处理（优先级 P2）

离线链路验证完成后，在线纠偏使用相同的逐帧同步契约。每个在线检测帧冻结自己的机器人
状态和在线流程上下文，查询并消费同帧 RobotSim observation。在线分段、检测结果和纠偏
命令继续遵守既有业务规则，本特性不得改变算法结果含义或命令触发条件。

验收场景：

- 假设在线纠偏正在运行，当有效相机帧和机器人状态到达时，RobotSim 查询、Vision 输入和
  UI 确认显示使用同一 frameId 的 observation。
- 假设上一运行会话停止后立即重新启动，上一会话迟到的 RobotSim 或 Vision 结果不得被路由
  到新会话，也不得清除或覆盖新会话的在途状态。
- 假设在线纠偏停止，系统必须安全清理当前帧、最新待处理帧、在途请求状态和 UI 中尚未
  确认的 observation，且不得因此生成新的纠偏命令。

### 用户场景三：模式与状态前置条件（优先级 P1）

正式在线和离线纠偏只能在 RobotSim 真实状态同步模式下运行。手动仿真场景模式继续用于 UI
展示和显式的非严格同步调试，但不得作为正式纠偏逐帧输入。

验收场景：

- 假设 RobotSim 处于手动仿真场景模式，当用户尝试启动正式在线或离线纠偏时，系统拒绝
  启动并给出必须切换到真实状态同步模式的明确说明。
- 假设尚未收到有效机器人状态，当纠偏流程收到相机帧时，系统明确报告该帧同步失败，不得
  使用默认零状态查询 RobotSim，也不得把该帧表现为成功。
- 假设正式纠偏正在运行，当 RobotSim 连接中断时，当前帧明确失败；连续同步失败达到停止
  条件后，系统通过既有完整停止流程结束当前纠偏任务。

### 用户场景四：同帧 UI 确认（优先级 P2）

在线和离线共用一条纠偏专用的逐帧 observation 通知通道，该通道与全局定位专属通知相互
独立。UI 可以暂存当前纠偏 observation，但只有当 Vision 返回同一运行会话且同一 frameId
的结果后，才能把它标记为“Vision 已消费”并显示为当前成功帧。

验收场景：

- RobotSim observation 和 Vision 结果的运行会话或 frameId 不匹配时，UI 不得把该
  observation 标记为已消费。
- 当前帧失败、流程停止、流程重启或 observation 被更新帧取代时，UI 必须清除尚未确认的
  observation，不得跨帧或跨会话复用。
- 阶段一 UI 至少显示当前纠偏同步状态、最近确认消费的 frameId 和最近一次逐帧查询错误；
  完整点数面板和可视化重构不属于本阶段。

### 功能需求

- 系统必须在相机帧到达运行时协调边界时，按值冻结相机帧、当时最新的 RobotState 和当前
  纠偏流程上下文。
- 系统不得声称阶段一实现了机器人状态与相机曝光时刻的硬同步；当前保证只覆盖运行时边界
  的状态快照。
- 系统必须使用冻结的同一份 RobotState 构造当前帧 RobotSim 查询，不得在派发或返回阶段
  改用更新的状态。
- 在线和离线纠偏必须使用逐帧 RobotSim observation，不得回退到 UI 或算法缓存中的最近
  observation。
- 无效、错误或 frameId 不匹配的 observation 必须使当前帧明确失败，并保留具体错误原因，
  不得使用上一帧有效数据冒充成功。
- 系统必须区分不同纠偏运行会话；停止或重启前产生的迟到 RobotSim 和 Vision 结果必须被
  丢弃。
- 系统必须采用有界背压：同一时间只允许一个逐帧查询在途，并最多保存一个最新待处理帧。
- 纠偏运行期间，普通 RobotSim 实时展示查询必须暂停派发，但系统继续接收并缓存最新机器人
  状态；纠偏停止后恢复普通实时查询。
- 纠偏不得依赖全局定位维护的段号；在线和离线只使用自身 RobotState 中的流程状态以及自身
  已有的纠偏上下文。
- 连续同步失败计数只包含无有效 RobotState、RobotSim 断开、查询失败、无效返回和错帧等
  同步链故障，不包含 Vision 正常执行后未检测到目标的业务结果。
- 任意一次成功的逐帧同步必须清零连续同步失败计数。
- 连续 3 帧同步失败后，系统必须通过既有完整停止路径终止当前纠偏任务、清理相关状态并向
  UI 报告原因；不得进入半运行状态，也不得生成纠偏命令。
- 阶段一的连续失败阈值固定为 3，且不向用户提供新的配置入口。
- 手动仿真场景的现有非严格同步缓存能力可以保留，但正式在线、离线路径不得使用该回退。

### 边界情况

- 首帧到达时尚无有效 RobotState。
- RobotSim 返回无效数据、空数据、错误 frameId 或明确通信错误。
- RobotSim 查询慢于相机帧到达速度。
- 在查询或 Vision 处理期间停止纠偏。
- 停止后立即重启，旧会话结果晚于新会话启动到达。
- RobotSim 运行中断开，随后产生连续同步失败。
- UI 已收到 observation，但尚未收到对应 Vision 结果时流程停止。
- 普通实时同步存在待处理状态时启动纠偏，或纠偏停止后恢复普通实时同步。

### 可验证成功标准

- 离线和在线纠偏测试中，所有提交给 Vision 的有效 observation 均与对应相机帧具有相同
  frameId，测试样本中错配数量为 0。
- 在持续高输入速率测试中，逐帧处理始终保持最多一个在途帧和一个最新待处理帧，队列不会
  随运行时间增长。
- 每种纠偏流程停止后，新增逐帧 RobotSim 查询数量为 0；迟到结果进入新会话的数量为 0。
- RobotSim 失败或错帧后，复用上一帧有效 observation 的次数为 0，且用户能够看到具体失败
  原因。
- 连续 3 帧同步故障会可靠终止当前纠偏流程；单次或两次故障后，后续成功帧可恢复处理并将
  失败计数清零。
- UI 标记为 Vision 已消费的 observation 与对应 Vision 结果在运行会话和 frameId 上完全
  一致，错配数量为 0。
- 离线专项场景全部通过后在线专项场景全部通过；两类流程均覆盖成功、背压、失败、停止、
  重启和迟到结果。
- 现有全局定位相关回归测试保持通过，且其产品行为、专属接口与实现逻辑没有改变。
- 现有视觉伺服/IBVS 内容没有发生修改。

### 测试与证据要求

- 建立在线/离线纠偏逐帧 RobotSim 专项测试套件。
- 专项测试必须覆盖阻塞、成功、失败、错帧和迟到返回，以验证背压及会话隔离。
- 相关服务测试必须覆盖 frameId 保留和原始错误信息保留，且现有调用方行为保持不变。
- 运行现有全局定位回归测试作为共享基础设施的保护，不修改测试来适应纠偏实现。
- 实施前查阅相关 legacy 行为，并在 docs 中记录影响当前在线/离线逐帧接入的重要发现。

### 明确排除

- 全局定位的新功能、重构或行为调整。
- 视觉伺服/IBVS 的任何修改。
- Vision、Localization 和 IBVS 算法重构。
- RobotSim 内部场景建模、几何求交和传感器算法。
- 二维激光点数与三维激光点数不一致问题。
- 焊缝点插入二维激光点列的现有适配行为。
- 图像回放、RobotComm fake transport 和完整无真实设备流程仿真。
- RobotSim 自动启动、自动加载场景和真实机器人运动命令。
- 完整 RobotSim 模式切换生命周期重构以及阶段三的完整 UI 可视化统一。

### 假设

- RobotSim 通信、真实状态同步和虚拟参考解析的现有基础能力可继续使用。
- Camera 和 RobotComm 能够分别提供相机帧及最新 RobotState，但当前两者没有共同硬件时间戳
  契约。
- Vision 已存在消费同帧相机图像、RobotState 和 RobotSim observation 的入口。
- 在线和离线纠偏不会与全局定位同时运行。
- 本特性可以复用全局定位已验证的公共机制，但不改变全局定位专属代码路径。
