# 20260831 RobotSim 仿真接入任务

## 1. 任务目标

在当前 RobotSim 通信和数据显示已经连通的基础上，将 RobotSim 提供的二维虚拟激光线、三维虚拟激光线和虚拟焊缝点正式接入在线纠偏、离线纠偏及相关可视化流程。

最终目标是建立下面的数据链：

```text
相机帧 + 该帧机器人状态
        -> RobotSim 状态同步与虚拟参考查询
        -> 同帧 DigitalTwinVisionLaserObservation
        -> Vision 在线/离线检测
        -> UI 可视化叠加
        -> Localization / IBVS 按需消费
```

## 2. 当前基础

当前项目已经具备以下能力：

- Qt 主程序可以连接 RobotSim 的 ZeroMQ 端口。
- 可以解析并显示二维虚拟激光点、三维虚拟激光点和二维虚拟焊缝点。
- 手动仿真场景模式会持续轮询 RobotSim，不发送真实机器人关节值。
- 真实场景模式可以将机器人和变位机关节值发送给 RobotSim，然后查询虚拟参考。
- `DigitalTwinVisionLaserObservation` 已定义统一的视觉仿真观测结构。
- Vision worker 已提供 `submitFrameWithRobotStateAndObservation(...)`，能够消费按帧绑定的相机图像、机器人状态和 RobotSim 观测。
- 全局定位已有按相机帧请求 RobotSim 先验的实现，可作为在线和离线流程的参考。

当前主要缺口：

- 在线纠偏和离线纠偏尚未稳定接入按帧 RobotSim 观测。
- 真实场景模式返回的 RobotSim 数据主要用于 UI 显示和缓存，没有完整进入在线/离线 Vision 处理链。
- 手动轮询结果与相机帧不是严格同步关系。
- 若要在没有真实机器人和真实相机的情况下完成全流程仿真，还需要图像回放和 RobotComm fake transport。

## 3. 数据源边界

完整的在线/离线仿真需要三类输入：

| 数据源 | 主要用途 | 提供方 |
|---|---|---|
| 二维激光线、三维激光线、焊缝点 | KCF、Gabor、ROI、三维参考和界面叠加 | RobotSim / DigitalTwin |
| 相机图像或离线回放图像 | 提取实际激光中心线和实际焊缝 | Camera 或回放设备 |
| `RobotState` 及流程标志 | 控制在线/离线采集、分段、结束和计算时机 | RobotComm 或 fake transport |

RobotSim 当前只负责虚拟参考，不替代真实图像源和机器人流程状态源。

## 4. 阶段一：在线/离线按帧接入 RobotSim

### 4.1 目标

将全局定位已有的逐帧 RobotSim 请求方式推广到：

- `OnlineCorrection`
- `OfflineCorrection`
- `GlobalLocalization`

确保一帧算法输入中的相机图像、机器人状态和 RobotSim 虚拟参考属于同一组冻结状态。

### 4.2 实施任务

- 在 `CRuntimeCoordinator::dispatchPendingVisionFrame()` 中统一判断当前跟踪目的是否需要 RobotSim 视觉先验。
- 相机帧到达时按值冻结：
  - `CameraFrame`
  - `RobotState`
  - 当前定位面或流程段编号
- 向 DigitalTwin worker 发起带 `frameId` 的 RobotSim 查询。
- 使用同一份冻结的机器人状态构造机器人和变位机关节向量。
- RobotSim 返回后调用：

  ```cpp
  submitFrameWithRobotStateAndObservation(
      frame,
      state,
      localizationSegmentIndex,
      observation);
  ```

- 在线和离线流程不得仅依赖 UI 中缓存的“最近一次”RobotSim 数据。
- 同步模式下，RobotSim 返回无效时必须让当前帧明确失败，不使用其他姿态的旧观测冒充当前帧数据。
- 保持“视觉算法慢于相机时只保留最新待处理帧”的现有背压策略，避免查询和图像任务无限堆积。
- 停止在线/离线流程时清除待处理帧、在途 RobotSim 请求标识和同步观测要求。

### 4.3 重点文件

- `UI/src/RuntimeCoordinator.cpp`
- `UI/include/RuntimeCoordinator.h`
- `UI/src/RuntimeWorkerAdapters.cpp`
- `UI/include/RuntimeWorkerAdapters.h`
- `UI/src/UiController.cpp`
- `DigitalTwin/include/DigitalTwinVisionTypes.h`

### 4.4 验收标准

- 在线和离线检测启动后不再出现 `simulated observation unavailable`。
- 相机帧 `frameId` 与传入 Vision 的 RobotSim observation `frameId` 一致。
- Vision 使用的虚拟激光线与 UI 当帧显示的数据来自同一 observation。
- RobotSim 单帧查询失败时，该帧输出明确失败原因。
- 连续运行时没有不断增长的相机帧或 RobotSim 请求队列。
- 停止流程后不再产生新的逐帧 RobotSim 查询。

## 5. 阶段二：明确两种 RobotSim 工作模式

### 5.1 手动仿真场景模式

用途：界面和算法联调。

- 用户直接在 RobotSim 中调整机器人、变位机或场景位置。
- Qt 主程序只持续请求虚拟激光线和焊缝点。
- Qt 不发送 `SET_Q_VEC`。
- 保留当前约 100 ms 的轮询机制。
- 允许作为非严格同步的 UI 叠加和算法调试输入。
- UI 必须明确显示“手动仿真场景，未发送真实关节值”。

### 5.2 真实状态同步模式

用途：正式在线、离线和定位流程。

- Qt 从 RobotComm 获取机器人和变位机状态。
- 每个需要处理的相机帧冻结对应 RobotState。
- DigitalTwin 向 RobotSim 写入对应关节值。
- 写入后查询该姿态下的激光线和焊缝点。
- 查询结果按同一 `frameId` 提交给 Vision。
- UI 必须明确显示当前为真实状态同步模式。

### 5.3 模式切换要求

- 两种模式不能同时驱动同一个 RobotSim 连接。
- 切换模式前应停止旧模式的轮询或待处理请求。
- 切换后清理旧 observation，避免旧场景数据进入新流程。
- 全局定位、在线纠偏或离线纠偏运行期间禁止切换 RobotSim 模式。
- 断开连接时清理连接状态、在途请求和 UI 叠加状态。

### 5.4 验收标准

- 手动模式移动 RobotSim 机器人时，界面激光线和焊缝点随场景更新。
- 手动模式日志和界面均明确表明没有发送 `SET_Q_VEC`。
- 同步模式能够持续发送机器人和变位机关节并收到对应虚拟参考。
- 模式切换后不会继续收到上一模式的轮询结果。
- 运行中的在线/离线流程无法误切换连接模式。

## 6. 阶段三：统一算法输入与 UI 可视化

### 6.1 目标

同一份 RobotSim observation 同时提供给 Vision、UI、Localization 和 IBVS，避免界面显示数据与算法实际消费数据不一致。

### 6.2 实施任务

- 将逐帧 RobotSim observation 作为单一事实来源。
- UI 使用 observation 中的以下字段绘制叠加：
  - `laserLineImagePoints_px`
  - `weldPointImage_px`
  - `hasWeldPointImage_px`
- Vision 使用同一 observation 完成：
  - KCF 模板初始化和更新
  - Gabor 方向约束
  - 焊缝点 ROI
  - gap 检测前置约束
- Localization 按流程收集同一 observation 中的 `laserLinePoints_mm`。
- IBVS 通过已有转换接口消费二维虚拟激光线和虚拟焊缝点。
- UI 状态区至少显示：
  - RobotSim 模式
  - 当前端口
  - observation 的 `frameId`
  - 二维激光点数
  - 三维激光点数
  - 焊缝点是否有效
  - 最近一次查询错误
- 无效 observation 应清除或标记当帧叠加，不得把失败表现为成功。

### 6.3 验收标准

- UI 显示的 `frameId` 与 Vision 当前处理帧一致。
- UI 显示的二维激光点数与 Vision 输入点数一致。
- 移动RobotSim姿态后，界面叠加和算法ROI同步变化。
- RobotSim断开或返回空数据时，UI明确显示失败状态。
- Localization和IBVS不直接创建RobotSim socket，也不解析RobotSim原始JSON。

## 7. 阶段四：无真实设备的完整流程仿真

### 7.1 目标

在不连接真实机器人和真实相机的情况下，可以完整演练在线纠偏和离线纠偏界面、状态机和算法数据流，但不向真实设备发送运动命令。

### 7.2 图像源任务

- 提供离线图片目录回放或明确的虚拟相机设备。
- 每张图像生成单调递增的 `frameId`。
- 支持启动、停止和安全回收。
- 回放速度可配置，默认不快于 Vision 实际处理能力。
- 保证图像尺寸和 RobotSim 传感器图像坐标定义一致。

### 7.3 RobotComm fake transport任务

- 使用现有 RobotComm 测试替身边界，不在 UI 中伪造业务结果。
- 提供机器人位姿、机器人关节和变位机关节状态。
- 按在线/离线流程产生必要的状态变化：
  - `traflag`
  - `posflag`
  - `detflag`
  - `corflag`
  - `onlineReverseCompleteFlag`
- 记录主程序发出的 `O`、`P` 等纠偏命令。
- 仿真模式下只记录命令，不连接或驱动真实机器人。
- 状态跳变需要有明确时序，避免同一帧重复触发边沿事件。

### 7.4 离线流程仿真

最小流程：

```text
选择离线纠偏任务
-> 启动仿真机器人状态和图像回放
-> 连续提交图像、RobotState和RobotSim先验
-> detflag 进入结束状态
-> 停止采集
-> 执行离线纠偏计算
-> 生成并记录O命令
```

验收标准：

- 离线检测能够自动开始和结束。
- 有效检测点能够按预期累计。
- 检测结束后进入计算状态。
- 计算结果能够进入待发送或完成状态。
- 仿真模式只记录命令，不向真实机器人发送。

### 7.5 在线流程仿真

最小流程：

```text
启动在线纠偏任务
-> 初始段检测
-> onlineReverseCompleteFlag 产生有效边沿
-> 连续提交图像、RobotState和RobotSim先验
-> 分段生成在线纠偏结果
-> 生成并记录P命令
-> detflag / corflag 推进或结束流程
```

验收标准：

- 初始段检测能够进入在线跟踪阶段。
- RobotSim先验能够连续进入KCF/Gabor处理。
- 在线纠偏点和gap结果能够更新UI。
- 分段状态变化不会重复提交同一条命令。
- 停止后相机、Vision、RobotSim请求和fake transport均安全退出。

## 9. 暂不处理事项

本任务暂不讨论或修改以下行为：

- 当前RobotSim二维激光点数与三维激光点数不一致的问题。
- 当前适配层将焊缝点插入二维激光点列的行为。
- RobotSim内部场景建模、OCCT求交或传感器算法实现。
- RobotSim自动启动和自动加载场景。
- 向真实机器人执行运动命令。
- `Vision/` 和 `Control/` 中与本次仿真数据接入无关的重构。

## 10. 推荐执行顺序

1. 完成在线/离线逐帧RobotSim observation接入。
2. 验证手动模式与真实状态同步模式的生命周期和互斥关系。
3. 统一UI叠加、Vision、Localization和IBVS的数据来源。
4. 接入图像回放和RobotComm fake transport。
5. 依次完成离线流程仿真、在线流程仿真和异常场景验收。

每个阶段完成后单独验证，不在前一阶段数据链尚未稳定时同时推进后续状态机仿真。
