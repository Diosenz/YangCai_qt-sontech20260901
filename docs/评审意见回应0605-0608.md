## 0605 总体架构与构建评审

来源文件：`docs/RLC代码评审0605（总体与 camera 模块）.txt`

| 评审意见 | 状态 | 回应 |
| --- | --- | --- |
| `vcpkg.json` 中 `$schema` 和 `features` 需要说明用途。 | 已回应 | 已在 `docs/environment_requirements.md` 中补充 vcpkg manifest 说明：`$schema` 用于编辑器字段提示和格式校验，不参与编译；`features` 是可选依赖集合，默认不启用，当前 `ibvs-yolo` 用于按需启用 ONNX Runtime。 |
| `CMakePresets.json` 希望只留下 debug/release；允许在无 OpenCV/ONNX 仍可编译时保留 without 配置。 | 部分采纳 | 当前保留 `qt-debug`、`qt-release` 和 `qt-debug-no-opencv`。保留 no-opencv 的原因是 IBVS 核心算法、离线回放和若干纯 C++ 测试可以不依赖 OpenCV，便于验证公共头拆分和可选依赖边界。ONNX Runtime 不作为默认 preset 暴露，只通过显式 feature/overlay 按需启用。 |
| 希望 OpenCV/ONNX 尽量由 vcpkg 管理。 | 部分采纳 | ONNX Runtime 已通过 vcpkg manifest feature `ibvs-yolo` 和项目 overlay port 管理，并且默认不启用。OpenCV 暂不放入 vcpkg manifest，原因是当前 legacy 算法迁移阶段要求 OpenCV 3.4.3，而 vcpkg 官方 OpenCV port 默认偏向 4.x；现阶段通过 `OpenCV_DIR` 指向本机 OpenCV 3.4.3 以降低行为差异。 |
| 根 `CMakeLists.txt` 不应在根层做 `find_package` 或 `add_executable`，`main.cpp` 应放入 UI 子项目；根 CMake 应只由多个子项目组成。 | 已修改 | 根 `CMakeLists.txt` 当前只保留全局 C++ 标准、公共编译选项、全局 option 和 `add_subdirectory(...)`。应用入口已移动到 `UI/src/main.cpp`，可执行目标由 `UI/CMakeLists.txt` 维护。 |
| `out/` 不应上传，写入 `.gitignore`。 | 已修改 | `.gitignore` 已包含 `out/`、`.vs/`、`build/`、`vcpkg_installed/`、`CMakeUserPresets.json` 等本地生成产物。 |
| `resource/` 如果是 Qt 目标资源，应放入 UI 子项目，不应暴露给其他子项目。 | 当前保留 | 当前仓库使用的是根级 `resources/`，并且现阶段主要作为运行资源/数据目录保留；尚未将其作为某个 Qt `.qrc` UI 资源目标接入。后续如果确认为 UI 专属资源，再迁入 `UI/`。 |
| `src/` 应删除，将 `main.cpp` 放入 UI 模块，各子项目直接放在根目录。 | 已修改 | 生产模块已提升为根级目录：`Camera`、`Localization`、`Vision`、`Control`、`IBVS`、`DigitalTwin`、`RobotComm`、`UI`。当前不存在根级生产 `src/` 目录，`UI/src/main.cpp` 是应用入口。 |
| 子项目名希望使用大驼峰，如 `Camera`、`DigitalTwin`、`IBVS`、`UI`。 | 已修改 | 当前 8 个生产模块均为根级大驼峰或约定大写缩写目录。 |

## 0608 IBVS 模块评审

来源文件：`docs/评审建议0608.txt`

| 评审意见 | 状态 | 回应 |
| --- | --- | --- |
| `./src/ibvs/include/IbvsTypes.h` 路径下的公共头内容过多，建议只保留真正全局共享类型。 | 已修改 | 原路径已随架构重构变为 `IBVS/include/ibvs/IbvsTypes.h`。已将 feature geometry 专属的 `IbvsFeatureGeometryParameters` 和 `IbvsFeatureGeometryResult` 从 `IbvsTypes.h` 移到 `IBVS/include/ibvs/IbvsFeatureGeometry.h`，减少公共类型聚合。 |
| `IbvsStatus` 适合作为公共状态类型，枚举值建议全大写加下划线。 | 已修改 | 已将 `IbvsStatus` 枚举值统一改为 `OK`、`EMPTY_INPUT`、`INVALID_ARGUMENT`、`NOT_ENOUGH_SAMPLES`、`DEGENERATE_GEOMETRY`、`SINGULAR_MATRIX`、`FILE_OPEN_FAILED`、`PARSE_ERROR`、`DEPENDENCY_DISABLED`、`RUNTIME_ERROR`，并同步 IBVS 源文件和测试调用点。 |
| 可考虑用 `std::expected<void, IbvsStatus>` 替代 `IbvsError`。 | 暂不采纳 | 当前项目根 CMake 仍使用 C++17；`std::expected` 属于 C++23。仓库中只有 `RobotComm` 单独启用 C++23 后使用 `std::expected`。如果为 IBVS 引入该接口，需要提高 IBVS 编译标准并重改大量错误返回接口，超出本轮小范围评审整改。因此保留 `IbvsError`，继续用 `IbvsStatus + message` 表达结构化错误和诊断信息。 |
| 如果 `IbvsError` 中字符串携带的信息重要，应补充 `IbvsStatus` 枚举项。 | 当前保留 | 现有状态枚举已覆盖当前错误类别，字符串主要用于诊断上下文，例如文件路径、解析失败原因、矩阵分解失败原因等。将这些上下文全部枚举化会导致枚举膨胀，降低诊断信息可读性。 |
| `PixelPoint::isFinite()` 是否必要；如果 Inf/NaN 是严重错误，可考虑用 `Eigen::Vector2d` 别名替代。 | 保留现设计 | 当前 `isFinite()` 是实际运行路径上的可恢复输入校验，不是冗余封装。起点检测、图像链、feature geometry 都会用它过滤非法像素点并返回结构化错误，而不是直接终止程序。已在 `tests/test_ibvs_core.cpp` 增加非有限起点返回 `DEGENERATE_GEOMETRY` 的测试覆盖。 |
| `IbvsHandEyeCalibration::valid` 标志容易被忘记检查，若无完整无效处理可简化。 | 已修改 | 已删除 `IbvsHandEyeCalibration::valid`，`jacobianLinear(...)` 始终使用传入的 `rotation`。默认 `rotation` 仍是单位阵，因此默认行为不变，同时避免“valid 为 false 时静默回退”的隐式状态。 |
| 过多有效性标志会增加维护成本，应通过设计减少。 | 已处理相关项 | 本轮只删除评审中指出的手眼标定 `valid` 标志；起点检测里的 `line.valid`、图像链候选里的 `valid` 表示算法中间结果是否成立，仍属于必要状态，不一并删除。 |
| `IbvsFeatureGeometryParameters` 默认值应提取到 `IbvsConfig.h` constexpr 常量。 | 已修改 | 新增 `IBVS/include/ibvs/IbvsConfig.h`，集中定义 `FEATURE_GEOMETRY_H1_MM_DEFAULT`、`FEATURE_GEOMETRY_H2_MM_DEFAULT`、`FEATURE_GEOMETRY_FOCAL_LENGTH_PX_DEFAULT` 等默认值；`IbvsFeatureGeometryParameters` 使用这些常量初始化。 |
| `IbvsFeatureGeometryParameters` 只在 feature geometry 中使用，应放到对应模块附近。 | 已修改 | 已将 `IbvsFeatureGeometryParameters` 放入 `IBVS/include/ibvs/IbvsFeatureGeometry.h`。保持类型名不变，减少调用点破坏，同时让参数定义靠近期望特征计算入口。 |
| `IbvsFeatureGeometry` 只有一个静态函数，可改为独立函数。 | 已修改 | 已删除 `IbvsFeatureGeometry` 单静态函数类，改为命名空间自由函数 `computeDesiredFeature(...)`，并同步 `IBVS/src/IbvsFeatureGeometry.cpp`、IBVS 测试和 `docs/ibvs_module_file_reference.md`。 |
| 若去掉 `IbvsFeatureGeometry` 类，参数结构体仍建议放在 `IbvsFeatureGeometry.h`。 | 已修改 | 已按该建议处理：`IbvsFeatureGeometryParameters` 和 `IbvsFeatureGeometryResult` 均位于 `IbvsFeatureGeometry.h`。 |
